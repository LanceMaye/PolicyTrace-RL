# 跨源关系与重复证据

规则版本 `policytrace-overlap-v1`。原始 SFT 对话 ID、scenario ID、RL Task ID 不是已证明共享的实例命名空间。编号相同、同一数据库文件、同类业务或高文本相似度均不能直接判为同一个任务。

检索使用明确的客户/邮箱/订单实体、NFKC+casefold+空白归一的 reason_for_call，以及局部词集合 Jaccard 排序的前三个 ≥0.50 候选。共享商品 ID、支付卡 ID 不作为客户身份检索键。文本相似度只找候选，没有任何按相似度自动排除的数据。实体文字、目标和详细证据只保存在私有文件中。

|---|---:|
| confirmed_same_instance | 0 |

| same_business_pattern_only | 609 |
| distinct_or_unknown：未决共享实体 | 4 |

这些是候选“对”的数量，不是应删除的 Task 数。涉及 272 个 RL Task；全组合空间为 563×1,000=563,000 对，检索不是穷举语义判断，不能把未检出的其余组合统称为已证明独立。

27 对 reason_for_call 归一后完全相同，但实体没有交集；它们说明同一模板可以用于不同案例，不构成同实例证明。没有任何跨源候选的状态修改动作及全部参数完全相同。SFT metadata 没有完整私有任务约束和评分结束条件；1,000 段 SFT 的写入前完整实体观测也不能与四份 RL 初态对应，因此没有确认同实例的充分依据。

4 对仅共享订单标识的未决关系形成一个跨源分组。本阶段把该组整体放在训练一侧，既保留合法 SFT 专家数据，又排除它们进入最终 Test。分组是保守隔离策略，不是把数字订单 ID 相同当成已确认重复。

匿名化例子：候选 A 的业务诉求文本相同，但客户和业务对象不同，属于共享业务模式；候选 B 只命中订单标识，缺少同一客户、完整约束及可核验初态，属于待审关系；没有能展示完整同实例证明的真实跨源案例。每对的来源 ID、规则、未知字段、参数比较、初态匹配及证据 SHA 见私有 `overlap_candidates.jsonl`。

内部也进行了实体/相同诉求候选检查。RL 内部 470 对：371 对共享业务模式、96 对不同或未知、3 对 probable；SFT 内部 815 对：779 对共享模式、36 对不同或未知。RL 的 3 对 probable 是同一写入参数、共享实体及同快照的待审关系，不能当作完整私有约束和相关初态已等价；generic 对象表示对账户任务没有订单对象 hash，亦不能据此确认。它们依实体关系整体分组，不跨 RL 分区。精确实例指纹重复组、完整 SFT 对话重复组、监督样本重复组均为 0。

所有 confirmed 判断要求身份、业务对象、目标、约束、结束条件、相关初态的非空有效哈希全部相等；缺失不是相等。synthetic 完整证据可以通过确认测试，修改客户/订单/目标/约束/初态均不能确认。这个测试通过不代表真实 SFT 具备这些字段。

残余风险是实体提取和局部文本检索可能漏掉改写、别名或未显示的上游种子关系；严格的字符串哈希也可能保守地漏报语义等价实例。当前结论是“未确认跨源同实例、发现并隔离可见风险”，不保证已经排除所有潜在来源污染。未决案例不会从成本视图删除。
