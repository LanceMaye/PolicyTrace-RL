# Reward 研究候选；尚未实现 R1

按先补诊断再判断是否需要奖励改动排序。所有方案保持最终官方 R0 不变；以下检索主题只供后续学习，不是已复现论文或已证明创新。

| 优先级/候选 | 问题与证据 | R0 覆盖及所缺内容 | 可验证性与潜在风险 | 实施前需要什么统计 | 后续检索主题 |
|---|---|---|---|---|---|
| P0 Simulator 稳定性审查 | 已观察 retail_152 认证前披露、retail_131 未规定国家字符串的措辞问题 | R0 不审查客户忠实度；先补环境诊断/配置稳定性，而非罚 Agent | 场景遵循可人工审查；把客户偏差算 Agent 过程惩罚会错误归因 | 固定开发集的目标漂移、编造资料、披露时机与终止偏差比例，分 Agent/User 归因 | user simulator fidelity、evaluation robustness |
| P0 字段规范与数据歧义 | 已观察 retail_131 仅 country 同义字符串使 R0=0 | R0 已检测精确差异，缺业务规范与错误分类；不放宽最终比较 | 可用公开工具说明/业务 schema 做规范化检查，不能依据隐藏答案修复 | 不同字段规范差异的数量、规范依据和对工具终态的影响；避免把真实错误当同义表达 | data validation、verifiable reward、canonicalization |
| P1 写入前认证/确认诊断 | 源码显示业务要求但工具未全检；Agent 绕过流程获高分仍是待观察假设 | R0 主要看终态/字符串，缺通用时序检查 | 可核验查询/写入顺序；自然语言确认语义需审查，机械规则可能惩罚合法表述或鼓励冗余确认 | 真实开发轨迹违规率、误报/漏报与人工一致性；确认非 Simulator 干扰 | verifiable process reward、trajectory-level reward |
| P1 只读拒绝质量 | 已观察 retail_152 可得 1 且通信约束为空；广泛过度拒绝为假设 | DB 不变难区分正确拒绝与什么也不做，先增加独立诊断 | 人工/受控测试可判断政策依据；奖励拒绝数容易过度拒绝，裁判可能偏表达 | 合法/非法请求分层成功率、错误拒绝/错误接受率与盲审一致性 | policy compliance evaluation、reward hacking |
| P2 重复动作与效率 | 不必要重复/冗长是源码可容许的假设，当前无广泛真实统计 | R0 终态奖励不直接惩罚重复，但 max_steps 失败；先统计成本 | 只读重复可数但重复有时是必要核对；步数罚分可能压制正确求证 | 成功任务调用/Token 分布、必要重复与无益重复人工区分，成本与成功率权衡 | cost-aware agents、step-level credit assignment |
| P2 稀疏奖励与全同组 | 长轨迹末端失败/GRPO 全零组是未来训练假设，当前没有训练组 | 终局 R0 无细粒度 credit；可能优先改采样/任务难度 | 状态 diff 可定位嫌疑，不能证明唯一因果步骤；过程奖励可被局部完成骗分 | 实际 Group Reward 均值/方差、全零/全同/有效组比例，失败类型与受控反事实 | DAPO dynamic sampling、GSPO、credit assignment |

任何候选转为实现前，记录证据集版本、设计假设、诊断准确性、潜在投机路径、对照方法与成本。只在开发集决定方案；最后冻结的测试集用于一次正式比较。
